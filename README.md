## :dart: O guia para alavancar a sua carreira

> Django é o framework web mais usado do Python: "baterias inclusas" desde o ORM e o painel administrativo automático até autenticação, formulários e proteção contra os ataques mais comuns (CSRF, SQL injection, XSS). É a base de produtos como Instagram, Spotify, Mozilla e Pinterest, e a escolha natural de quem já programa em Python e quer construir aplicações web robustas rápido. Este guia reúne roadmap, tutorial oficial, documentação, livros, canais, ferramentas do ecossistema (Django REST Framework, Celery, Wagtail) e um capítulo sobre usar IA na prática com Django — tudo verificado, com prioridade para conteúdo gratuito e em português.

## 🗺️ Roadmap
- [roadmap.sh — Django Roadmap](https://roadmap.sh/django) — Guia passo a passo da comunidade para se tornar um desenvolvedor Django, com projetos sugeridos e trilha por tópico.
- [O que é Django? (LearnDjango)](https://learndjango.com/tutorials/what-is-django-python) — Explicação do que é o framework, sua filosofia e quando escolhê-lo.
- [Como aprender Django em 2026 (LearnDjango)](https://learndjango.com/tutorials/how-learn-django) — Roteiro atualizado de William Vincent (autor de Django for Beginners) sobre por onde estudar o framework.
- [Filosofias de design do Django (documentação oficial)](https://docs.djangoproject.com/en/stable/misc/design-philosophies/) — Os princípios por trás de cada decisão de design do framework — entender isso ajuda a prever "o jeito Django" de resolver um problema.
- [Django release process (documentação oficial)](https://docs.djangoproject.com/en/stable/internals/release-process/) — Como o Django versiona e lança novas versões: um novo *feature release* a cada ~8 meses, com uma LTS a cada duas versões.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Fundamentos de Python** — variáveis, funções, orientação a objetos, `venv`/`pip`. Django pressupõe Python intermediário.
2. **Primeiro projeto** — `django-admin startproject`, `startapp`, servidor de desenvolvimento (`runserver`).
3. **Models e ORM** — `models.py`, migrations (`makemigrations`/`migrate`), querysets, relacionamentos (chave estrangeira, muitos-para-muitos).
4. **Admin, views e templates** — painel administrativo automático, views baseadas em função e em classe, sistema de templates.
5. **Forms e autenticação** — `ModelForm`, validação, sistema de usuários e permissões do próprio Django.
6. **Testes e segurança** — `django.test`, checklist de deploy, proteção contra CSRF/XSS/SQL injection.
7. **APIs** — Django REST Framework: serializers, viewsets, autenticação por token/JWT.
8. **Produção** — arquivos estáticos, variáveis de ambiente, Gunicorn, Docker, PostgreSQL, deploy.
9. **Especialização** — tarefas assíncronas (Celery), WebSockets (Django Channels), CMS (Wagtail), performance e cache.

## 🚀 Por onde começar
1. **Instale o Python** e crie um ambiente virtual; depois instale o Django com `pip install django` (veja a [página oficial de downloads](https://www.djangoproject.com/download/) e o [guia de instalação](https://docs.djangoproject.com/en/stable/intro/install/)).
2. **Crie seu primeiro projeto** seguindo o [Django Hello, World (LearnDjango)](https://learndjango.com/tutorials/django-hello-world) ou o [How to Install Django (LearnDjango)](https://learndjango.com/tutorials/how-install-django).
3. **Siga o tutorial oficial** — [Writing your first Django app, part 1](https://docs.djangoproject.com/en/stable/intro/tutorial01/): constrói um app de enquetes (polls) do zero e é o ponto de partida recomendado pela própria documentação.
4. **Faça o Django Girls Tutorial em português** — [tutorial.djangogirls.org/pt](https://tutorial.djangogirls.org/pt/): constrói um blog completo, do "Olá, mundo" ao deploy, com explicações pensadas para quem nunca programou.
5. **Assista a um curso em vídeo em português** em paralelo à leitura da documentação — veja a seção [🔤 Sites e cursos](#-sites-e-cursos-para-aprender-django) abaixo.
6. **Leia a visão geral oficial do framework** — [Django overview](https://www.djangoproject.com/start/overview/) — mostra em poucos minutos como model, view, template e admin se encaixam.
7. **Depois do básico, aprenda a expor APIs** com o [Django REST Framework](https://www.django-rest-framework.org/).
8. **Publique um projeto no GitHub** e faça o deploy — planos gratuitos como Railway, Render, Fly.io ou PythonAnywhere funcionam bem para começar.

Seu primeiro projeto em poucos comandos:

```bash
python3 -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install django
django-admin startproject meusite
cd meusite
python manage.py runserver
```

## 🛠️ Ferramentas
### APIs e autenticação
- [Django REST Framework](https://www.django-rest-framework.org/) — O padrão de fato para construir APIs REST com Django.
- [Django Ninja](https://django-ninja.dev/) — APIs rápidas com Django usando type hints, no estilo FastAPI.
- [django-allauth](https://docs.allauth.org/en/latest/) — Autenticação completa: login social, e-mail, MFA e mais.
- [djangorestframework-simplejwt](https://django-rest-framework-simplejwt.readthedocs.io/en/latest/) — Autenticação JWT para o Django REST Framework.
- [dj-rest-auth](https://dj-rest-auth.readthedocs.io/en/latest/) — Endpoints prontos de registro, login e recuperação de senha para APIs REST.
- [drf-spectacular](https://drf-spectacular.readthedocs.io/en/latest/) — Geração automática de documentação OpenAPI/Swagger a partir do DRF.
- [django-cors-headers](https://pypi.org/project/django-cors-headers/) — Configura CORS para seu backend Django ser consumido por um front-end separado.

### Produtividade e depuração
- [django-debug-toolbar](https://django-debug-toolbar.readthedocs.io/en/latest/) — Painel de depuração com queries SQL, tempo de resposta e mais, direto no navegador.

## 🤖 IA na prática
Django é maduro e muito bem documentado — isso torna os assistentes de IA bons para gerar boilerplate (models, serializers, views, migrations), mas o ORM e o sistema de apps têm convenções específicas que a IA erra com frequência, especialmente ao misturar versões diferentes do framework.

**Para aprender**
- Peça para a IA explicar um traceback de migration (`django.db.utils.ProgrammingError`, `InconsistentMigrationHistory`) e sugerir como resolver sem perder dados.
- Peça exercícios com testes usando `django.test.TestCase` ou `pytest-django` sobre o tópico que está estudando: você escreve a solução, o teste diz se passou.
- Peça para transformar uma view baseada em função em uma Class-Based View (ou vice-versa) e explicar o trade-off de cada abordagem.
- Use a IA para revisar o relacionamento entre seus models e conferir se bate com o que você pretendia modelar antes de rodar `makemigrations`.

**Para trabalhar**
- Use GitHub Copilot, Cursor ou Claude Code para gerar serializers e viewsets do Django REST Framework a partir dos models, escrever testes e migrations, e explicar querysets complexos.
- Depois de aceitar uma sugestão que mexe no banco, rode `python manage.py makemigrations --check --dry-run` e **leia** a migration gerada antes de aplicar — IA às vezes cria migrations que fazem `DROP COLUMN` de forma destrutiva.
- Peça para a IA revisar suas views em busca do problema de N+1 queries (sugestão de `select_related`/`prefetch_related`) — é um erro comum que a IA introduz ao gerar views rapidamente.
- [GitHub Copilot](https://github.com/features/copilot) — Autocomplete e chat com IA no editor; gratuito para estudantes e com plano free.
- [Cursor](https://cursor.com/) — Editor baseado no VS Code com IA integrada ao fluxo de trabalho.
- [Claude Code](https://code.claude.com/docs/en/overview) — Agente de código no terminal: escreve testes, revisa migrations e explica tracebacks do Django.

**Limites e boas práticas**
- IA **inventa parâmetros e métodos do ORM** que não existem na versão instalada do Django — confira sempre na documentação oficial da versão em uso (`python -c "import django; print(django.VERSION)"`).
- Desconfie de código que monta SQL com f-strings/`.format()` em vez de usar o ORM ou os `params` do `cursor.execute()` — é o padrão de SQL injection mais repetido por IA.
- Nunca aceite sugestões que exponham `SECRET_KEY`, credenciais de banco ou deixem `DEBUG = True` em produção.
- Migrations geradas por IA precisam ser lidas por um humano antes de rodar em produção — revertê-las depois de aplicadas em um banco com dados reais pode ser destrutivo.
